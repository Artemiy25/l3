## Задание

Взяв за основу результат ЛР2 (наблюдаемые суда с сигналами SOS и поиском трёх ближайших
к терпящему бедствие судну судов), добавить к регрессионным тестам нагрузочные и запускать их
в сценарии непрерывной интеграции.

## Решение

Код программы не изменился, добавлены генератор нагрузочных тестов и скрипт нагрузочного теста.

### Генератор нагрузочных тестов

Генератор `bin/stressgen` (`src/stressgen/stressgen.cpp`) читает файл шаблонов команд
и выводит заданное количество случайных команд:

```bash
bin/stressgen test/stress/templates.txt 50000 2025 > build/stress.test
```

Генератор настраивается шаблонами `test/stress/templates.txt`. Пример шаблонов:

```
add {ship} {tonnage} {tonnage} {type}
move {ship} {coord} {coord}
sos {newsignal} {ship} | nearest {lastsignal} | close {lastsignal}
nearest {signal}
```

| Подстановка | Что подставляется |
|---|---|
| `{ship}` | наименование судна `s0`…`s49` |
| `{tonnage}` | тоннаж 1…100000 т (сухой и полный выбираются независимо, поэтому примерно половина `add` и `update` нарушает правило «полный не меньше сухого») |
| `{type}` | тип судна `cargo`, `tanker` или `cruise` |
| `{coord}` | координата −100…100 миль |
| `{newsignal}` | новый номер сигнала SOS: 1, 2, 3, … |
| `{lastsignal}` | номер, выданный последним `{newsignal}` |
| `{signal}` | номер одного из последних 20 сигналов |

Частота команды задаётся числом повторов шаблона в файле. Несколько команд через ` | ` образуют
сценарий и выводятся подряд — так проверяется полный цикл спасения: сигнал SOS → поиск трёх
ближайших судов → (судно сместилось, повторный поиск) → завершение спасения.
Без сценариев случайные `nearest` и `close` почти никогда не попадали бы в только что
принятый сигнал. В шаблоны специально добавлены команды с ошибками: программа должна отвечать
на них сообщением, а не падать.

При одинаковом seed генератор выдаёт одни и те же команды, поэтому найденную ошибку можно повторить.

### Скрипт нагрузочного теста

`test/stress-test [количество команд] [лимит времени, мс]`:
1. генерирует файл с командами;
2. запускает `bin/lab` и замеряет время работы;
3. проверяет:
   - программа не упала (код возврата 0; при нарушении инварианта `assert` аварийно завершает программу);
   - время работы не больше лимита;
   - в выводе нет «Неизвестная команда», то есть генератор и программа согласованы.

Пример запуска:

```
Команд: 50000
Время выполнения: 1069 мс (допустимо: 30000 мс)
Нагрузочный тест пройден
```

### Результаты

Что программа выполнила за один прогон (50 000 команд, seed 2025):

| Показатель | Количество |
|---|---|
| ответов с ошибкой | ≈ 37 500 |
| принято сигналов SOS | 427 |
| успешных поисков трёх ближайших судов | 473 |
| из них найдено меньше трёх судов | 47 |
| завершённых спасений | 377 |

Ошибок в ответах много, так и задумано: случайные команды часто обращаются к несуществующим
судам и сигналам, а половина значений тоннажа неправильная. Так проверяется и обработка ошибок,
и основная функциональность.

Нагрузочный тест показал особенность модели: если в момент сигнала SOS рядом нет ни одного
свободного судна с известными координатами, спасатели не назначаются и сигнал нельзя закрыть,
пока повторный `nearest` не найдёт суда. Такое судно считается терпящим бедствие и не
назначается спасателем по другим сигналам. Генератор повторяет поиск только по недавним сигналам,
поэтому к концу прогона таких судов становится больше и доля принятых сигналов падает.
Это соответствует правилам модели из ЛР2 и не является ошибкой программы.

### Сценарий CI

- `build-code` — сборка `bin/lab` и `bin/stressgen`;
- `test-all` — регрессионные тесты ЛР1–ЛР2 (`test/run-tests`);
- `stress-test` — нагрузочный тест: 50 000 команд, лимит 30 с;
- `pages` — документация Doxygen и отчёт о покрытии.

Генератор собирается без `--coverage`: это вспомогательная программа, в покрытие она не входит.
Покрытие считается по регрессионным тестам и составляет более 95 %.
